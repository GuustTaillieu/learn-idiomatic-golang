Lesson 0012: The Final Assembly: cmd/server & OS Signal Handling

Target: Wire our queue, store, and HTTP server together in a real runnable binary with zero-downtime graceful shutdown.

Milestone: All package unit tests passed with -race! Your HTTP layer now cleanly separates routing, serialization, and state tracking.

1. The Composition Root: What belongs in main()?

In senior Go architecture, packages inside internal/ should never know how the application is configured or executed. They are building blocks.

The Composition Root is cmd/server/main.go. It is the only place in the codebase that imports all concrete types, wires them together, and manages the process lifecycle.

2. Modern Signal Handling: signal.NotifyContext

How does a production Go server catch Ctrl+C or Kubernetes SIGTERM without abruptly killing in-flight tasks?

Go 1.16+ introduced the elegant signal.NotifyContext:

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

When an interrupt arrives, ctx.Done() fires! That gives our application the trigger to initiate graceful shutdown.

3. The Graceful Teardown Sequence

When ctx.Done() fires, we execute teardown in strict reverse order:

  1. Stop accepting new HTTP traffic: 
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
_ = server.Shutdown(shutdownCtx)
    This closes the listening network port and allows active HTTP requests to complete.
  2. Stop the worker queue: 
    q.Stop()
    This closes the task channel and waits for all active workers to finish draining.
  3. Exit cleanly: All database connections or files close, and the process terminates with code 0.

4. A Real Production Processor: Simulating Work

In our tests, we used a mock processor. In our real binary, let's create a realistic processor (e.g. an order processor that simulates billing and shipping by logging and sleeping for 500ms):

type OrderProcessor struct{}

func (p *OrderProcessor) Process(ctx context.Context, payload string) error {
    slog.Info("processing order", "order", payload)
    select {
    case <-time.After(500 * time.Millisecond):
        slog.Info("order fulfilled successfully", "order", payload)
        return nil
    case <-ctx.Done():
        return ctx.Err()
    }
}

Your Hands-On Challenge: Build cmd/server/main.go

  1. Create directory: cmd/server/.
  2. Create file: cmd/server/main.go:
    • Declare package main.
    • In main():
      1. Set up signal context with signal.NotifyContext.
      2. Initialize s := store.NewMemoryStore().
      3. Initialize a processor (e.g. &OrderProcessor{}).
      4. Initialize q := queue.NewQueue(p, s).
      5. Start 3 background workers: q.Start(ctx, 3).
      6. Initialize handler := httpapi.NewHandler(q, s).
      7. Create srv := &http.Server{Addr: ":8080", Handler: handler.Routes()}.
      8. Launch the server in a goroutine: 
        go func() {
    if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
        slog.Error("server failed", "error", err)
    }
}()
      9. Wait for signal: <-ctx.Done().
      10. Run shutdown: srv.Shutdown(...) then q.Stop().
  3. Run your server: 
    go run ./cmd/server
  4. Test with curl from a second terminal: 
    curl -i -X POST http://localhost:8080/tasks -d '{"payload":"laptop_order_99"}'
