Lesson 0008: Wiring the Store & Avoiding Package Cycles

Target: Connect our thread-safe Store to the Queue engine and master Go's interface decoupling.

Review of Your internal/store Package:
  • ✅ Flawless RWMutex usage: Write locks for Save, read locks for GetById. ThreadSanitizer ran cleanly.
  • ✅ Clean Error Handling: Returning queue.ErrTaskNotFound when lookups fail.
  • 💡 Idiomatic Go Naming Convention: In Go, acronyms stay uniformly uppercase (e.g. GetByID rather than GetById, and TaskID rather than TaskId). Also, plain Get(ctx, id) is often preferred over GetByID when there is only one lookup method.

1. The Real-World Pipeline: The Store Meets the Worker

Our e-commerce pipeline now has two key components:

  • The Queue (dispatches tasks to worker goroutines).
  • The Store (tracks the current state of tasks).

When a worker runs, it needs to update the store at each lifecycle step so the customer's dashboard reflects reality:

  1. Worker picks up task: task.Status = StatusRunning → save to store!
  2. Processor finishes: task.Status = StatusCompleted (or StatusFailed) → save to store!

2. The Compiler Trap: Package Dependency Cycles

If Queue needs to call store.Save(...), should package queue import package store?

NO! Look at what internal/store/memory.go imports:

import "github.com/.../internal/queue" // for queue.Task

If internal/queue imports internal/store, Go will throw a compile-time error:

import cycle not allowed:
    package internal/queue
    imports internal/store
    imports internal/queue

3. The Senior Go Solution: Consumer-Defined Interfaces

In Go, interfaces are satisfied implicitly. A package does not need to know who implements its interface.

Instead of importing store.MemoryStore, package queue defines the minimal behavior it requires right inside internal/queue/queue.go:

type Store interface {
    Save(ctx context.Context, task *Task) error
}

Now:

  • queue only depends on its own local Store interface. Zero knowledge of MemoryStore, Postgres, or Redis!
  • MemoryStore in internal/store already satisfies this interface because it has a Save(ctx, task) method!
  • Zero import cycle!

Your Hands-On Challenge: Wire Store into Queue

  1. In internal/queue/queue.go:
    • Define the consumer interface: 
      type Store interface {
    Save(ctx context.Context, task *Task) error
}
    • Add store Store to the Queue struct.
    • Update constructor: func NewQueue(processor Processor, store Store) *Queue.
    • In worker(), update the store when the task starts and finishes: 
      task.Status = StatusRunning
_ = q.store.Save(ctx, task)

if err := q.processor.Process(ctx, task.Payload); err != nil {
    task.Status = StatusFailed
} else {
    task.Status = StatusCompleted
}
_ = q.store.Save(ctx, task)
  2. In internal/queue/queue_test.go:
    • Create a dummy store or use store.NewMemoryStore() in your tests.
    • Verify that after q.Stop(), querying the store shows all tasks have StatusCompleted!
  3. Run go test -v -race ./...!
