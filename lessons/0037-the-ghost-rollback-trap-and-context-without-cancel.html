Lesson 0037: The Ghost Rollback Trap & context.WithoutCancel

Target: Prevent failed database rollbacks during timeouts, master Go 1.21's context.WithoutCancel, and fix mock test signatures.

Brilliant Architectural Evolution:

You noticed that database operations inside cleanup closures need a context, so you upgraded your interface in internal/domain/queue.go to:

type Processor[T any] interface {
    Process(ctx context.Context, item T) (cleanup func(context.Context) error, err error)
}

This was a great senior realization! But it uncovers one of Go's most notorious production concurrency traps: The Ghost Rollback.

1. The Ghost Rollback Trap

Imagine a customer places an order, and the payment gateway times out after 3 seconds: context.DeadlineExceeded.

Your pipeline detects the failure and initiates the compensating rollback:

// ⚠️ Production Trap:
if err != nil {
    cleanup(ctx) // ctx is ALREADY CANCELLED!
}

What happens when cleanup executes p.InventoryStore.ReleaseStock(ctx, stock)?

  1. database/sql receives ctx.
  2. Before sending the SQL query to SQLite, ExecContext checks ctx.Err().
  3. Because ctx has already expired, it immediately returns context canceled without executing the SQL query!
  4. The Result: Your rollback silently fails, inventory remains locked, and money isn't refunded!

2. The Fix: context.WithoutCancel (Go 1.21+)

Before Go 1.21, developers were forced to choose between two bad options:

  • Pass ctx → Fails with context canceled.
  • Pass context.Background() → Works, but loses all Request IDs, Trace IDs, and Logger context!

In Go 1.21, the Go core team solved this with context.WithoutCancel:

func executeRollback(ctx context.Context, rollback func(context.Context) error) error {
    if rollback == nil {
        return nil
    }

    // 1. Sever the cancellation signal while KEEPING all context values (Request ID, Logger):
    detachedCtx := context.WithoutCancel(ctx)

    // 2. Give the rollback its own dedicated, clean timeout:
    rollbackCtx, cancel := context.WithTimeout(detachedCtx, 3*time.Second)
    defer cancel()

    // 3. The SQL queries in rollback now execute successfully!
    return rollback(rollbackCtx)
}
