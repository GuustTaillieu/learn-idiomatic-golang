Lesson 0041: 12-Factor Configuration & Fail-Fast Startup

Target: Eliminate hardcoded constants, implement cloud-native 12-factor configuration using Go standard library, and build strict fail-fast validation.

Look At What You've Built:

Your service is now a complete, production-grade distributed application with a transactional outbox, parallel saga rollbacks, real-time SSE streaming, rate limiting, and live pprof diagnostics! But take a look at cmd/server/main.go:

db, _ := sql.Open("sqlite", "file:orders.db?cache=shared&mode=rwc") // Hardcoded!
srv.Addr = ":8080"                                                // Hardcoded!
queue.Start(ctx, 3)                                               // Hardcoded 3 workers!

In production cloud environments (Docker, Kubernetes, AWS), hardcoded settings prevent smooth deployments and multi-environment staging.

1. Why Avoid Bloated Config Frameworks (e.g. Viper)?

Many beginners import third-party monoliths (like Viper) that pull in 20+ transitive dependencies, add YAML/JSON reflection overhead, and increase compile times. In idiomatic Go, senior engineers use the Standard Library First approach:

  • os.LookupEnv / os.Getenv for environment variables.
  • flag package for CLI arguments.
  • Strict struct validation before starting the runtime.

2. The Architecture of internal/config

package config

import (
    "errors"
    "flag"
    "os"
    "strconv"
    "time"
)

type Config struct {
    Port         string
    DatabaseURL  string
    WorkerCount  int
    RateLimit    float64
    RateBurst    int
    ShutdownTime time.Duration
}

func Load() (*Config, error) {
    cfg := &Config{
        Port:         getEnv("PORT", "8080"),
        DatabaseURL:  getEnv("DATABASE_URL", "file:orders.db?cache=shared&mode=rwc"),
        WorkerCount:  getEnvInt("WORKER_COUNT", 3),
        RateLimit:    getEnvFloat("RATE_LIMIT", 5.0),
        RateBurst:    getEnvInt("RATE_BURST", 10),
        ShutdownTime: 5 * time.Second,
    }

    // Allow CLI flag overrides (e.g. -port=9090 -workers=5)
    flag.StringVar(&cfg.Port, "port", cfg.Port, "HTTP server port")
    flag.IntVar(&cfg.WorkerCount, "workers", cfg.WorkerCount, "Worker pool size")
    flag.Parse()

    if err := cfg.Validate(); err != nil {
        return nil, err
    }

    return cfg, nil
}

func (c *Config) Validate() error {
    if c.WorkerCount <= 0 {
        return errors.New("WORKER_COUNT must be > 0")
    }
    if c.Port == "" {
        return errors.New("PORT cannot be empty")
    }
    return nil
}

3. The Fail-Fast Startup Flow in cmd/server/main.go

func main() {
    cfg, err := config.Load()
    if err != nil {
        slog.Error("Configuration invalid, failing fast", "error", err)
        os.Exit(1)
    }

    // Now all components are dynamically driven by cfg:
    db, err := sql.Open("sqlite", cfg.DatabaseURL)
    ...
    queue.Start(ctx, cfg.WorkerCount)
    srv.Addr = ":" + cfg.Port
}

Your Hands-On Challenge

  1. Create internal/config/config.go:
    • Define Config struct with Port, DatabaseURL, WorkerCount, RateLimit, RateBurst.
    • Implement Load() (*Config, error) reading from environment variables with fallback defaults.
    • Implement Validate() error checking that workers > 0, port is not empty, and rate limit > 0.
  2. Create internal/config/config_test.go:
    • Test that defaults load correctly.
    • Test that invalid values (e.g. WorkerCount: 0) trigger a validation error!
  3. In cmd/server/main.go:
    • Call cfg, err := config.Load() at the very beginning of main().
    • Replace hardcoded values with fields from cfg.
  4. Run: 
    go test -v -race ./...
