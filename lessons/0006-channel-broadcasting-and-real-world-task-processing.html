1. Deep Dive: Why ch <- struct{}{} Hangs (1-to-1 vs Broadcast)

In Stop(), you wrote:

q.stopChan <- struct{}{} // ❌ Can deadlock!

stopChan is an unbuffered channel (make(chan struct{})). In Go, sending to an unbuffered channel is a synchronous rendezvous:

  • The sender blocks until another goroutine is actively waiting to receive from it.
  • If nobody is calling Submit() when Stop() is called, q.stopChan <- struct{}{} waits forever. Stop() never finishes!
  • Even if someone is waiting, sending a single value only wakes up one goroutine. If 5 requests were waiting to submit, 4 would remain stuck.

The Senior Go Solution: close(q.stopChan)

In Go, closing a channel is the universal broadcast signal:

close(q.stopChan) // ✅ Wakes up EVERY listener immediately!

When a channel is closed, any goroutine waiting on case <-q.stopChan: unblocks instantly. And closing never blocks!

2. Connecting to Reality: Why are we building this?

Let's ground this in a real production problem: an E-Commerce Order Fulfillment System.

When a user clicks "Place Order":

  1. The HTTP server cannot run credit card billing, PDF receipt generation, and warehouse inventory sync synchronously inside the request—doing so would take 4 seconds and cause timeouts if 1,000 customers order at once.
  2. Instead, the HTTP handler builds a Task (e.g. Payload: "order_id_9482") and calls q.Submit(ctx, task). It responds to the user in 2 milliseconds: "Order accepted, processing in background!"
  3. Our background worker goroutines pick up the task and run q.processor.Process(ctx, task.Payload).

The Next Missing Piece: What happened to the task?

If the user later opens their dashboard to check their order, they ask: "Is my receipt ready?"

Right now, our worker does:

_ = q.processor.Process(ctx, task.Payload) // We discard the result!

In a real system, the task has a lifecycle:

  1. Before processing starts: task.Status = StatusRunning.
  2. If Process(...) succeeds: task.Status = StatusCompleted.
  3. If Process(...) fails: task.Status = StatusFailed.
