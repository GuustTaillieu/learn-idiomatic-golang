Lesson 0011: HTTP Dependency Injection, PathValue, & httptest

Target: Refine your HTTP handlers with clean dependency injection, native routing, and lightning-fast tests with net/http/httptest.

Review of Your internal/httpapi/handler.go:
  • ✅ Streaming JSON: You used json.NewDecoder(r.Body).Decode(&req) and json.NewEncoder(w).Encode(task). That avoids reading entire payloads into temporary memory buffers!
  • ✅ Structured Logging: You used standard library log/slog with key-value pairs ("task_id", task.ID).
  • ✅ HTTP Status Codes: Proper usage of http.StatusBadRequest, http.StatusNotFound, and http.StatusOK.

1. Refinement #1: Use Native r.PathValue("id")

In handleGetTask, you wrote:

id := r.URL.Path[len("/tasks/"):] // ⚠️ Fragile string slicing

Because you registered the route with mux.HandleFunc("GET /tasks/{id}", ...), Go 1.22+ gives you a built-in extractor:

id := r.PathValue("id") // ✅ Safe, clean, standard!

It handles trailing slashes and path normalization automatically.

2. Refinement #2: True Dependency Injection

Currently, your NewHandler instantiates concrete objects inside itself:

func NewHandler() *Handler {
    p := processor.NewMockProcessor()
    s := store.NewMemoryStore()
    return &Handler{
        queue: queue.NewQueue(p, s),
        store: s,
    }
}

Notice you already defined beautiful interfaces at the top:

type Queue interface {
    Submit(ctx context.Context, task *queue.Task) error
}

type Store interface {
    Save(ctx context.Context, task *queue.Task) error
    Get(ctx context.Context, id string) (*queue.Task, error)
}

In senior Go, Handler should receive its dependencies from the outside:

func NewHandler(queue Queue, store Store) *Handler {
    return &Handler{queue: queue, store: store}
}

func (h *Handler) Routes() http.Handler {
    mux := http.NewServeMux()
    mux.HandleFunc("POST /tasks", h.handleCreateTask)
    mux.HandleFunc("GET /tasks/{id}", h.handleGetTask)
    return mux
}

Why? This allows cmd/server/main.go to pass the real production worker queue, while our tests can pass mock or test queues effortlessly.

3. Refinement #3: The "Pending" State Race Condition

In handleCreateTask, you create the task and submit it:

task := queue.NewTask(req.Payload)
h.queue.Submit(r.Context(), task)

The Catch: What if the customer's browser calls GET /tasks/{id} right away, while the task is still waiting in the channel buffer? The worker hasn't picked it up yet, so the task isn't in the store! The customer gets a false 404 Not Found.

The Fix: Save the task in the store (as StatusPending) before or right when submitting:

task := queue.NewTask(req.Payload)
if err := h.store.Save(r.Context(), task); err != nil {
    http.Error(w, "failed to save task", http.StatusInternalServerError)
    return
}
if err := h.queue.Submit(r.Context(), task); err != nil {
    // ...
}

4. Testing HTTP with net/http/httptest

In Go, you don't need to boot a real TCP server to test HTTP handlers! httptest.NewRecorder() acts as an in-memory http.ResponseWriter:

req := httptest.NewRequest("GET", "/tasks/123", nil)
rec := httptest.NewRecorder()

handler.Routes().ServeHTTP(rec, req)

if rec.Code != http.StatusOK { ... }
