Lesson 0047: Type-Safe Connect-RPC Client & In-Memory Integration Testing

Target: Learn how Go microservices and CLI tools talk to your Connect-RPC server. Write an end-to-end integration test with httptest.Server, and connect the web frontend!

Review of Your Connect-RPC Server Implementation:

You defined proto/order/v1/order.proto, compiled it with protoc, created internal/http/order_rpc.go, and mounted it onto internal/http/handler.go using:

osp, osh := orderv1connect.NewOrderServiceHandler(NewOrderRPCServer(h.orderStore))
mux.Handle(osp, osh)

Notice how clean this is: your RPC server is running on the exact same HTTP port (8080) alongside your REST endpoints, your SSE event stream, and your pprof diagnostics. No extra ports, no complex Envoy proxy, zero overhead!

1. The Two Halves of RPC: Server and Client

Building the server is only half the battle. In distributed architectures, other microservices (or worker nodes, or CLI tools) need to consume your RPC API.

Instead of manually making HTTP calls with http.Post, serializing JSON, and parsing status codes, Connect generated a type-safe client stub for you: orderv1connect.NewOrderServiceClient!

2. Writing In-Memory Black-Box Integration Tests

Using Go's net/http/httptest package, you can spin up a real in-memory HTTP server, bind your Connect handler, and make real network RPC calls via the generated client without opening external firewall ports:

func TestOrderRPCService_Integration(t *testing.T) {
    store := memory.NewOrderStore()
    mux := http.NewServeMux()
    path, handler := orderv1connect.NewOrderServiceHandler(NewOrderRPCServer(store))
    mux.Handle(path, handler)

    server := httptest.NewServer(mux)
    defer server.Close()

    // Create type-safe client pointing to test server
    client := orderv1connect.NewOrderServiceClient(server.Client(), server.URL)

    // Call CreateOrder
    req := connect.NewRequest(&v1.CreateOrderRequest{
        ItemId: "00000000-0000-0000-0000-000000000001",
        Amount: 5,
    })
    res, err := client.CreateOrder(context.Background(), req)
    if err != nil {
        t.Fatalf("CreateOrder failed: %v", err)
    }

    if res.Msg.OrderId == "" {
        t.Fatalf("Expected non-empty OrderId")
    }
}

3. Restoring the Dashboard File Server in handler.go

In internal/http/handler.go, you had commented out the file server. In Go 1.22+, you can simply mount:

mux.Handle("/", web.FileServer())

Go 1.22's mux matches the most specific prefix first. That means /order.v1.OrderService/* goes to Connect-RPC, /orders/* goes to REST, /events goes to SSE, and everything else routes cleanly to your embedded static web dashboard!
