Target: Master one of Go's most unique, elegant production concurrency weapons: request deduplication with singleflight.

  • 💡 Subtle Concurrency Gotcha to Fix: In Queue[T], you placed retries int on the struct (q.retries++). If you run 3 workers concurrently, they share q.retries without a lock, and Item A's retries affect Item B! Retries belong to the item, not the queue.

1. The Problem: The "Thundering Herd" in Polling Systems

In Lesson 0026, we learned that clients poll GET /orders/{id} every second to check if their order has finished processing.

Now imagine what happens during a big product drop or flash sale:

  1. 500 users refresh the page at the exact same second to check stock for a hot sneaker (GET /inventory/{item_id}).
  2. 500 concurrent HTTP request goroutines hit your server at the exact same millisecond.
  3. Without protection, your server fires 500 identical SQL queries to SQLite simultaneously: 
    SELECT * FROM inventory WHERE item_id = 'sneaker-123'; -- x 500!
  4. SQLite gets locked, CPU spikes, database pool exhausts, and responses slow down to a crawl.

2. The Go Secret Weapon: singleflight.Group

In most languages, solving this requires external distributed caches like Redis or complex locking. In Go, the standard library team built a magical concurrency primitive: golang.org/x/sync/singleflight.

How Singleflight Works:

500 concurrent goroutines call: g.Do("item-123", fn)

↓

Goroutine 1: Executes the SQL query!

Goroutines 2 through 500: Wait seamlessly in memory!

↓

Goroutine 1 finishes → Result is shared with all 500 goroutines simultaneously!

Result: 500 incoming HTTP requests result in exactly ONE database query! The other 499 requests get the result without touching the database at all.

3. The Idiomatic Go Implementation

import "golang.org/x/sync/singleflight"

type CachedInventoryStore struct {
    store domain.InventoryStore
    group singleflight.Group
}

func (c *CachedInventoryStore) Get(ctx context.Context, itemID domain.ItemID) (*domain.Stock, error) {
    // 💡 The key identifies duplicate in-flight requests:
    key := fmt.Sprintf("get_stock:%s", itemID)

    val, err, shared := c.group.Do(key, func() (any, error) {
        // Only ONE goroutine executes this function at a time for this key!
        return c.store.Get(ctx, itemID)
    })
    if err != nil {
        return nil, err
    }

    if shared {
        slog.Info("Deduplicated query via singleflight!", "item_id", itemID)
    }

    return val.(*domain.Stock), nil
}

4. Why Singleflight is Unique to Go

Singleflight relies on Go's lightweight goroutines and channels. Because goroutines only cost ~2KB of RAM, having 500 goroutines pause and wait on a Go channel until the first goroutine returns costs virtually zero CPU and memory.
