Lesson 0045: Embedded Database Migrations & Idempotent Seeding

Target: Eliminate scattered CREATE TABLE calls, centralize schema definitions into versioned SQL files embedded into your Go binary, and seed initial catalog data so stress tests pass 100%.

Your Key Insight from Stress Testing:
"I didn't seed the database so all tasks fail because of insufficient stock, but that's no problem that could easily be fixed..."

You hit a fundamental rite-of-passage in backend engineering! Right now, tables are created via individual CREATE TABLE IF NOT EXISTS statements scattered across:

  • internal/sqlite/order.go
  • internal/sqlite/inventory.go
  • internal/sqlite/item.go

And when a fresh server starts, the database has zero items and zero stock! So every order placed by cmd/stress or the web dashboard naturally fails stock reservation.

1. The Problem with Scattered DDL in Go Repositories

  1. Separation of Concerns: OrderStore is responsible for storing and retrieving orders (Data Manipulation / DML). It should not manage database schema creation (Data Definition / DDL).
  2. Schema Evolution: CREATE TABLE IF NOT EXISTS cannot add new columns, alter constraints, or migrate existing data.
  3. Circular Foreign Keys: orders references items(id). If NewOrderStore runs before NewItemStore, table creation can fail!

2. The Go embed.FS Migration Engine

Instead of pulling in heavy third-party migration frameworks, senior Go teams embed raw .sql files directly into the single binary:

// internal/sqlite/migrations.go
package sqlite

import (
    "database/sql"
    "embed"
    "fmt"
    "io/fs"
    "sort"
)

//go:embed migrations/*.sql
var migrationFiles embed.FS

func Migrate(db *sql.DB) error {
    entries, err := fs.ReadDir(migrationFiles, "migrations")
    if err != nil {
        return fmt.Errorf("reading migrations directory: %w", err)
    }

    sort.Slice(entries, func(i, j int) bool {
        return entries[i].Name() < entries[j].Name()
    })

    for _, entry := range entries {
        content, err := migrationFiles.ReadFile("migrations/" + entry.Name())
        if err != nil {
            return fmt.Errorf("reading migration %s: %w", entry.Name(), err)
        }
        if _, err := db.Exec(string(content)); err != nil {
            return fmt.Errorf("executing migration %s: %w", entry.Name(), err)
        }
    }
    return nil
}

3. The Structure of Your Migrations

Organize your database initialization in internal/sqlite/migrations/:

  • 00001_init_schema.sql: Creates items, inventory, and orders tables with correct foreign keys and indexes.
  • 00002_seed_initial_data.sql: Uses INSERT OR IGNORE to insert item 00000000-0000-0000-0000-000000000001 ("Gopher Plushie") with 1,000 units of stock.

Your Hands-On Challenge

  1. Create directory internal/sqlite/migrations/:
    • 00001_init_schema.sql: Centralize the table creation for items, inventory, and orders.
    • 00002_seed_initial_data.sql: Insert the default item and 1,000 units of stock using INSERT OR IGNORE.
  2. Create internal/sqlite/migrations.go:
    • Use //go:embed migrations/*.sql to embed the SQL files.
    • Implement Migrate(db *sql.DB) error to execute all migrations in sorted sequence.
  3. Clean up your stores:
    • Remove the scattered CREATE TABLE IF NOT EXISTS queries from NewOrderStore, NewInventoryStore, and NewItemStore.
  4. In cmd/server/main.go:
    • Call sqlite.Migrate(db) right after opening the database connection!
  5. Run your stress test: 
    go run cmd/server/main.go
# In another terminal:
go run cmd/stress/main.go -c 10 -n 100
  6. Open http://localhost:8080: Watch all 100 orders succeed and complete in real time!
