Lesson 0040: Production Diagnostics: pprof Profiling & Goroutine Leak Hunting

Target: Learn the ultimate weapon of senior Go engineers: diagnosing CPU spikes, heap growth, and goroutine leaks in live production software using Go's built-in pprof.

Review of Your Rate Limiter Implementation:
  • 🎉 Senior Cleanup Return: Returning (rateLimiter *IPRateLimiter, cleanupFunc func()) in NewIPRateLimiter was a great move! It ensures the background cleaner goroutine can be stopped without leaking.
  • 💡 Mutex as Value & Unexported Fields: In IPRateLimiter, you declared Connections as an exported field with a pointer mutex mu *sync.RWMutex. In Go, mutexes should be direct values (mu sync.RWMutex), and data protected by the mutex should be unexported (connections) so callers cannot bypass the lock.
  • 💡 Middleware Order for Observability: In main.go, RateLimitMiddleware is on the outside, so 429 rejections are returned before LoggingMiddleware runs. Moving RequestIDMiddleware and LoggingMiddleware to the very outside ensures you can observe and log rejected 429 traffic in production!

1. The Problem: How Do You Debug Production Without Crashing?

Imagine your Go service has been running in production for 2 weeks. Suddenly:

  • CPU spikes to 95%.
  • Memory usage creeps up by 200MB every day.
  • Goroutine count climbs from 20 to 15,000!

In other languages, you might need heavy commercial agents (Datadog, New Relic) that slow down the service. In Go, Google built the gold standard of profilers directly into the runtime: net/http/pprof.

2. Exposing pprof in Modern http.ServeMux

In internal/http/handler.go, register the standard pprof handlers:

import "net/http/pprof"

// In Routes():
mux.HandleFunc("GET /debug/pprof/", pprof.Index)
mux.HandleFunc("GET /debug/pprof/cmdline", pprof.Cmdline)
mux.HandleFunc("GET /debug/pprof/profile", pprof.Profile)
mux.HandleFunc("GET /debug/pprof/symbol", pprof.Symbol)
mux.HandleFunc("GET /debug/pprof/trace", pprof.Trace)

3. How Senior Go Engineers Inspect a Running Server

A. Check All Active Goroutines (Instant Leak Check)

curl -s http://localhost:8080/debug/pprof/goroutine?debug=1

Prints every active goroutine and the exact line of code where it is currently waiting! If you see 1,000 goroutines waiting on a channel send, you found your leak in 5 seconds.

B. Analyze Memory Heap Allocations

go tool pprof http://localhost:8080/debug/pprof/heap

Opens an interactive shell. Type top10 to see which functions hold the most memory, or list <FuncName> to view line-by-line allocations!

C. 30-Second CPU Profiling Under Load

go tool pprof http://localhost:8080/debug/pprof/profile?seconds=10

Samples CPU instruction pointers across all cores to pinpoint which algorithms consume CPU.
