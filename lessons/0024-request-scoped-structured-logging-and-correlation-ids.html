1. The 3 Approaches to Logging in Go

Approach 1: Inject *slog.Logger into every struct

type Queue struct { logger *slog.Logger }

Verdict: Great for static component logging, but terrible for request-scoped fields. If a logger lives on Queue, it cannot automatically know which order_id or request_id is being processed on worker goroutine #3!

Approach 2: Global slog.Default() with manual args

slog.Info("processing", "order_id", order.ID)

Verdict: Repetitive and error-prone. You have to remember to type "order_id", order.ID on every single line across 15 different functions.

Approach 3 (The Gold Standard): Context-Scoped Logger

Attach a logger enriched with request metadata to ctx at the boundary (HTTP middleware or worker loop). Any function taking ctx automatically inherits the fields!

2. The Context-Scoped Logger Pattern in Go

Just like you did with lib.WithTx(ctx, tx), we can create a clean logger helper in internal/lib/logger.go:

package lib

import (
    "context"
    "log/slog"
)

type loggerKey struct{}

// ContextWithLogger embeds an enriched logger into context.
func ContextWithLogger(ctx context.Context, logger *slog.Logger) context.Context {
    return context.WithValue(ctx, loggerKey{}, logger)
}

// Logger retrieves the logger from context, falling back to slog.Default().
func Logger(ctx context.Context) *slog.Logger {
    if l, ok := ctx.Value(loggerKey{}).(*slog.Logger); ok {
        return l
    }
    return slog.Default()
}

Why this is brilliant:

  1. Zero Nil Panics: If a function receives a plain context.Background(), lib.Logger(ctx) safely falls back to slog.Default().
  2. Clean Signatures: You don't have to add logger *slog.Logger to struct constructors or function parameters. ctx is already passed everywhere!
  3. Automatic Context Enrichment: When a worker starts processing an order: 
    log := slog.With("order_id", order.ID.String(), "item_id", order.ItemID.String())
ctx = lib.ContextWithLogger(ctx, log)

// Now inside PaymentProcessor, ReserveStock, etc.:
lib.Logger(ctx).Info("reserving stock")
// Output automatically has order_id and item_id attached!

3. The HTTP Correlation ID Middleware

In microservices, when a customer hits POST /orders, we attach a Request ID so we can trace that single request through the entire system:

func RequestIDMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        requestID := r.Header.Get("X-Request-ID")
        if requestID == "" {
            requestID = uuid.New().String()
        }

        w.Header().Set("X-Request-ID", requestID)

        // Enrich the logger for this entire HTTP request:
        logger := slog.With("request_id", requestID)
        ctx := lib.ContextWithLogger(r.Context(), logger)

        next.ServeHTTP(w, r.WithContext(ctx))
    })
}
