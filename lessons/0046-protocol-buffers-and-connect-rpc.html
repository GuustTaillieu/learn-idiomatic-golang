Lesson 0046: Type-Safe Distributed Contracts with Protocol Buffers & Connect-RPC

Target: Move beyond fragile, handwritten REST endpoints. Define your API in Protocol Buffers, generate type-safe Go server handlers, and mount them directly to standard Go HTTP muxes using Connect-RPC.

Answering Your Question:
"Teach me the best frontend/microservice tool to use with Go (maybe gRPC or something..?)"

In traditional Go backends, teams used gRPC. But gRPC has a massive flaw: it does not work natively in web browsers! Standard browsers cannot send HTTP/2 trailers, forcing teams to run an Envoy reverse-proxy just to bridge React/TypeScript frontends to Go backend services.

Enter Connect-RPC (developed by Buf, endorsed by the Go community). Connect-RPC gives you the exact same schema-driven speed of gRPC and Protobuf, but it runs directly over standard HTTP/1.1 and HTTP/2 POST requests with JSON or Protobuf. Best of all: it mounts directly as a standard http.Handler on Go's http.ServeMux!

1. Why Contract-First APIs Beat Ad-hoc REST/JSON

  • Zero Serialization Drift: The .proto contract is the single source of truth. TypeScript types and Go types are generated from the exact same schema.
  • Backward Compatibility: Protobuf tag numbers (= 1, = 2) allow non-breaking field additions and deprecations over time.
  • Dual Protocol Support: The exact same endpoint can accept binary Protobuf from backend microservices and standard JSON from browsers and curl!

2. The Workflow

  1. Define the service contract in proto/order/v1/order.proto.
  2. Run code generation using protoc with protoc-gen-go and protoc-gen-connect-go.
  3. Implement the generated Go service interface (OrderServiceHandler).
  4. Mount it to your existing internal/http/handler.go routes via mux.Handle(path, handler).
  5. Test it via curl with plain JSON or via Connect RPC!

3. The Proto Contract

syntax = "proto3";

package order.v1;

option go_package = "github.com/GuustTaillieu/idiomatic-go/proto/order/v1;orderv1";

service OrderService {
  rpc CreateOrder(CreateOrderRequest) returns (CreateOrderResponse);
  rpc GetOrder(GetOrderRequest) returns (GetOrderResponse);
}

message CreateOrderRequest {
  string item_id = 1;
  int32 amount = 2;
}

message CreateOrderResponse {
  string order_id = 1;
  string status = 2;
}

message GetOrderRequest {
  string order_id = 1;
}

message GetOrderResponse {
  string order_id = 1;
  string item_id = 2;
  int32 amount = 3;
  string status = 4;
}

Your Hands-On Challenge

  1. Create directory proto/order/v1/ and write order.proto with the schema above.
  2. Compile the protocol buffer contract into Go and Connect code: 
    protoc --go_out=. --go_opt=paths=source_relative \
       --connect-go_out=. --connect-go_opt=paths=source_relative \
       proto/order/v1/order.proto
    (Verify that order.pb.go and order.connect.go are generated!)
  3. In internal/http/order_rpc.go:
    • Create an OrderRPCServer implementing the generated OrderServiceHandler interface.
    • Implement CreateOrder and GetOrder delegating to your orderStore.
  4. In internal/http/handler.go:
    • Mount the generated Connect handler: 
      path, handler := orderv1connect.NewOrderServiceHandler(NewOrderRPCServer(h.orderStore))
mux.Handle(path, handler)
  5. Run your server: 
    go run cmd/server/main.go
  6. Call your new RPC endpoint via standard curl with JSON: 
    curl -X POST http://localhost:8080/order.v1.OrderService/CreateOrder \
     -H "Content-Type: application/json" \
     -d '{"item_id": "00000000-0000-0000-0000-000000000001", "amount": 2}'
  7. Verify all tests pass: 
    go test -v -race ./...
