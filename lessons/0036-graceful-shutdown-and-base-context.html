Lesson 0036: Streaming Teardown & http.Server.BaseContext

Target: Eliminate the context deadline exceeded error on shutdown, understand how Go manages HTTP request context lifecycles, and achieve instant sub-10ms graceful termination.

The Bug You Encountered: 
^C2026/10/02 18:11:09 INFO Shutting down server...
2026/10/02 18:11:14 ERROR Failed to shutdown server error="context deadline exceeded"

Notice the exact 5-second gap: 18:11:09 to 18:11:14. That matches your context.WithTimeout(..., 5*time.Second)! Why did it wait the full 5 seconds?

1. The Root Cause: Why srv.Shutdown() Hung

According to the official Go standard library documentation for http.Server.Shutdown(ctx):

"Shutdown works by first closing all open listeners, then closing all idle connections, and then waiting indefinitely for connections to return to idle and then shut down."

Crucial detail: http.Server.Shutdown() does NOT cancel the r.Context() of in-flight active HTTP requests! It politely waits for handlers to return on their own.

Now look at your GET /events SSE handler:

for {
    select {
    case <-r.Context().Done():
        return
    case event := <-subscriber:
        ...
    }
}

Because the browser tab is still open, and because srv.Shutdown() does not cancel r.Context(), your SSE handler was happily waiting in an infinite loop! After 5 seconds, the shutdown timeout expired and logged context deadline exceeded.

2. The Standard Library Fix: http.Server.BaseContext

In Go 1.13, the Go team added a field to http.Server specifically for this: BaseContext.

BaseContext allows you to specify the parent context for all incoming HTTP requests. If you set it to your top-level signal.NotifyContext:

import "net"

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
defer stop()

srv := &http.Server{
    Addr:    ":8080",
    Handler: httpHandler,
    // 💡 When Ctrl+C is pressed, ctx is cancelled.
    // This immediately cancels r.Context() inside EVERY active HTTP handler!
    BaseContext: func(l net.Listener) context.Context {
        return ctx
    },
}

What Happens When You Press Ctrl+C:

User hits Ctrl+C → signal.NotifyContext cancels ctx

↓

BaseContext propagates cancellation → r.Context().Done() fires in SSE handler!

↓

handleGetEvents exits → defer Unsubscribe runs → connection closes in 0.2ms!

↓

srv.Shutdown() completes in 2ms with ZERO errors!

3. Bonus Safety Net: Forceful Close Fallback

In production, if an unruly HTTP request somehow refuses to exit before the timeout, senior engineers always follow up with srv.Close() to forcefully tear down remaining sockets:

if err := srv.Shutdown(shutdownCtx); err != nil {
    slog.Warn("Graceful shutdown timed out, closing forcefully", "error", err)
    _ = srv.Close()
}
