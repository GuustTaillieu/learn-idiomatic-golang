1. Why database/sql in Senior Go?

In the Go ecosystem, while third-party ORMs like GORM exist, senior Go teams and tech companies overwhelmingly prefer standard database/sql (often with query tools like sqlc). Why?

  • Built-in Connection Pooling: sql.DB is not an open connection—it is a thread-safe connection pool! It manages opening, reusing, and closing connections under high concurrency automatically.
  • Zero Reflection Overhead: Direct scanning with rows.Scan(&t.ID, ...) is blazingly fast and predictable.
  • ACID Transactions: Full support for transactions via db.BeginTx(ctx, nil) with commit and rollback.

2. The Blank Import Idiom (_ "modernc.org/sqlite")

How does Go connect database/sql to a specific database engine without hardcoding dependencies? The Driver Pattern.

import (
    "database/sql"
    _ "modernc.org/sqlite" // 👈 The blank identifier!
)

In Go, an import with _ runs the package's init() function without bringing its identifiers into scope. The SQLite package's init() calls sql.Register("sqlite", &Driver{}) under the hood. Then, calling sql.Open("sqlite", "tasks.db") knows exactly how to speak to SQLite!

3. The SQLite Schema & Upsert Query

Our database schema for tasks:

CREATE TABLE IF NOT EXISTS tasks (
    id TEXT PRIMARY KEY,
    payload TEXT NOT NULL,
    status TEXT NOT NULL,
    created_at DATETIME NOT NULL
);

When saving a task, we use SQLite's ON CONFLICT (Upsert) so updating an existing task's status doesn't fail:

INSERT INTO tasks (id, payload, status, created_at)
VALUES (?, ?, ?, ?)
ON CONFLICT(id) DO UPDATE SET
    status = excluded.status;

Security Rule: Always use ? placeholders! Never concatenate strings into SQL queries.

4. Translating sql.ErrNoRows to Domain Errors

When s.db.QueryRowContext(...) finds no matching row, row.Scan(...) returns sql.ErrNoRows.

A senior Go package hides database-specific implementation details from callers. We translate it to our domain sentinel error:

if errors.Is(err, sql.ErrNoRows) {
    return nil, queue.ErrTaskNotFound // Clean domain error!
}

5. The Beauty of Interface Decoupling

Notice something amazing: because Queue and Handler only depend on:

type Store interface {
    Save(ctx context.Context, task *Task) error
    Get(ctx context.Context, id string) (*Task, error)
}

Our new SQLiteStore will satisfy this interface 100%! We can swap from in-memory to a real SQLite database file by changing only one line in main.go, without touching a single line of queue or HTTP code.
