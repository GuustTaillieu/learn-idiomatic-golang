Lesson 0042: Structured Error Classification & Boundary Translation

Target: Prevent the "Everything is 404 or 500" anti-pattern. Map domain errors to standard HTTP status codes using Go 1.13+ error unwrapping, and protect internal infrastructure details.

The Problem in Your Code Today:

Take a close look at internal/http/handle_get_order.go:

order, err := h.orderStore.Get(r.Context(), domain.OrderID(parsedId))
if err != nil {
    http.Error(w, "order not found", http.StatusNotFound)
    return
}

Notice what happens if SQLite crashes, the disk fills up, or the database connection drops: orderStore.Get() returns an error, and your HTTP handler tells the client 404 Not Found!

In distributed systems, this is a dangerous bug: client SDKs check for 404 and conclude "The order doesn't exist, let me retry creating it", leading to duplicated orders and phantom charges while your database is failing.

1. What Caused Your Config Test Panic?

Before fixing HTTP errors, let's understand why your configuration test panicked:

panic: /tmp/go-build.../config.test flag redefined: port

In Go's standard library, top-level functions like flag.StringVar(...) and flag.Parse() operate on a package-level global singleton: flag.CommandLine.

  • When TestLoad ran, it registered -port on the global flag.CommandLine.
  • When TestLoad_InvalidWorkerCount ran immediately after, it called Load() again, which attempted to register -port a second time on the same global FlagSet. The flag package panics when flags are redefined!

By creating an isolated fs := flag.NewFlagSet("server", flag.ContinueOnError) inside Load(args ...string), each call to Load() operates on its own clean flag set without mutating global state.

2. The Architecture of Boundary Error Translation

A production web service spans multiple concentric layers:

  1. Domain Layer (internal/domain): Defines business entities and sentinel errors (ErrOrderNotFound, ErrInvalidOrder, ErrInsufficientStock). Knows nothing about HTTP or SQL.
  2. Storage Layer (internal/sqlite): Translates driver errors (like sql.ErrNoRows) into domain errors (domain.ErrOrderNotFound) using %w.
  3. API / Boundary Layer (internal/http): Inspects errors via errors.Is and converts them into HTTP status codes:
    • domain.ErrOrderNotFound → 404 Not Found
    • domain.ErrInvalidOrder → 400 Bad Request
    • domain.ErrInsufficientStock → 409 Conflict
    • context.DeadlineExceeded → 504 Gateway Timeout
    • Unclassified errors → Logged with request ID, returns generic 500 Internal Server Error (never leaking internal SQL queries or file paths to clients!).

3. Building the Error Responder

// internal/http/errors.go
package http

import (
    "errors"
    "log/slog"
    "net/http"

    "github.com/GuustTaillieu/idiomatic-go/internal/domain"
)

func respondError(w http.ResponseWriter, r *http.Request, err error) {
    switch {
    case errors.Is(err, domain.ErrOrderNotFound), errors.Is(err, domain.ErrItemNotFound):
        http.Error(w, err.Error(), http.StatusNotFound)
    case errors.Is(err, domain.ErrInvalidOrder):
        http.Error(w, err.Error(), http.StatusBadRequest)
    case errors.Is(err, domain.ErrInsufficientStock):
        http.Error(w, err.Error(), http.StatusConflict)
    default:
        slog.ErrorContext(r.Context(), "unhandled server error", "error", err)
        http.Error(w, "internal server error", http.StatusInternalServerError)
    }
}
