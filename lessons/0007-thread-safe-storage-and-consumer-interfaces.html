Lesson 0007: Thread-Safe Storage & Consumer-Defined Interfaces

Target: Build a thread-safe repository for order tracking and learn why Go maps crash under concurrency.

Win: You fixed the broadcast shutdown with close(q.stopChan) and added lifecycle status transitions (StatusRunning, StatusCompleted, StatusFailed) to worker(). All tests pass with zero race conditions!

1. The Real-World Problem: "Where did my order go?"

In our E-Commerce pipeline, when the customer clicks "Buy Now", the HTTP API generates a task with an ID and returns it immediately: "Order #abc-123 placed!"

Two seconds later, the customer's browser asks: GET /orders/abc-123.

Currently, our tasks only exist transiently while floating in the channel! Once a worker finishes, the task is gone from memory. If the customer queries their order status, we have nothing to show them.

We need a Task Store (repository) to persist and look up tasks by their ID.

2. Why Go Maps Crash Under Concurrency

In Go, built-in maps are NOT thread-safe. If two goroutines access a map concurrently and at least one is a write:

fatal error: concurrent map writes
fatal error: concurrent map read and map write

This is not a regular error you can catch with if err != nil. It is an unrecoverable runtime panic that instantly terminates the entire application!

To safely store tasks in memory, our store struct must pair a map with a sync.RWMutex:

type MemoryStore struct {
    mu    sync.RWMutex
    tasks map[string]*Task
}
  • Save(ctx, task): Modifies the map → requires exclusive lock (s.mu.Lock() / defer s.mu.Unlock()).
  • Get(ctx, id): Only reads from the map → allows multiple concurrent readers (s.mu.RLock() / defer s.mu.RUnlock()).

3. Idiomatic Design: Consumer-Defined Interfaces

In languages like Java or C#, developers often create massive interface hierarchies upfront (e.g. IRepository<T> with 20 methods). In idiomatic Go, we follow: "Define interfaces where they are consumed, keeping them as small as possible (1-2 methods)."

What does our system actually need right now?

type Store interface {
    Save(ctx context.Context, task *Task) error
    Get(ctx context.Context, id string) (*Task, error)
}

Your Hands-On Challenge: Build internal/store

  1. Create directory: internal/store/.
  2. Create file: internal/store/memory.go:
    • Declare package store.
    • Define type MemoryStore struct holding a sync.RWMutex and tasks map[string]*Task.
    • Write constructor func NewMemoryStore() *MemoryStore that initializes the map with make(map[string]*Task).
    • Implement Save(ctx context.Context, task *queue.Task) error: Acquires write lock, stores s.tasks[task.ID] = task, returns nil.
    • Implement Get(ctx context.Context, id string) (*queue.Task, error): Acquires read lock. If found, returns the task and nil. If not found, returns nil, queue.ErrTaskNotFound.
  3. Create a test file: internal/store/memory_test.go:
    • Test saving a task and retrieving it by ID.
    • Test querying an unknown ID and verifying errors.Is(err, queue.ErrTaskNotFound).
  4. Run go test -v -race ./internal/store!
