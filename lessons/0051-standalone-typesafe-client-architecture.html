Lesson 0051: The Standalone Type-Safe Client & Cross-Repository Contracts

Target: Build a standalone client that communicates with your backend in the most optimal, type-safe way—with zero dependencies on internal server code.

How Distributed Systems Separate Clients From Servers:

In enterprise engineering, clients (mobile apps, web frontends, and external microservices) must never import internal server packages like SQLite, outbox, or business sagas.

Go enforces this at compile time: any code inside an internal/ directory is forbidden from being imported outside this module! Only the public contract in proto/order/v1/ is exported.

1. What Makes This the "Most Optimal & Type-Safe" Way?

  1. Binary Protobuf Wire Format: Unlike JSON (which requires text serialization, quotes, and string parsing), binary Protocol Buffers pack integers and UUIDs into raw varints and bytes. It is 5x–10x faster and cuts payload size by ~70%!
  2. Compile-Time Type Safety: If the server renames a field or changes a type, the client fails at compile-time (go build), not at runtime in production!
  3. Zero Duplication: Both the server and client share the exact same generated Go structs from order.proto.

2. The Architecture of cmd/client/main.go

package main

import (
    "context"
    "flag"
    "fmt"
    "net/http"
    "os"
    "time"

    "connectrpc.com/connect"
    orderv1 "github.com/GuustTaillieu/idiomatic-go/proto/order/v1"
    "github.com/GuustTaillieu/idiomatic-go/proto/order/v1/orderv1connect"
)

func main() {
    serverURL := flag.String("url", "http://localhost:8080", "Server base URL")
    flag.Parse()

    // 1. High-performance HTTP client with connection pooling
    httpClient := &http.Client{
        Timeout: 5 * time.Second,
        Transport: &http.Transport{
            MaxIdleConns:        100,
            MaxIdleConnsPerHost: 20,
            IdleConnTimeout:     90 * time.Second,
        },
    }

    // 2. Type-safe generated client stub (imports ZERO internal packages!)
    client := orderv1connect.NewOrderServiceClient(httpClient, *serverURL)

    // Example CreateOrder RPC
    res, err := client.CreateOrder(context.Background(), connect.NewRequest(&orderv1.CreateOrderRequest{
        ItemId: "00000000-0000-0000-0000-000000000001",
        Amount: 2,
    }))
    if err != nil {
        fmt.Fprintf(os.Stderr, "Error creating order: %v\n", err)
        os.Exit(1)
    }

    fmt.Printf("Order Created Successfully!\nID:     %s\nStatus: %s\n", res.Msg.OrderId, res.Msg.Status)
}

Your Hands-On Challenge

  1. Create cmd/client/main.go:
    • Support two subcommands: create and get:
      • create -item <id> -amount <n> → calls client.CreateOrder.
      • get -order <id> → calls client.GetOrder.
    • Verify: Check your imports! Ensure cmd/client/main.go imports only proto/order/v1 and orderv1connect—zero imports from internal/!
  2. Start your server in one terminal: 
    go run cmd/server/main.go
  3. In another terminal, test creating an order using your standalone client: 
    go run cmd/client/main.go create -item 00000000-0000-0000-0000-000000000001 -amount 3
  4. Retrieve the order details using the returned Order ID: 
    go run cmd/client/main.go get -order <ORDER_ID>
  5. Open your browser dashboard at http://localhost:8080: Watch the order created by your standalone CLI client show up and complete in real time!
