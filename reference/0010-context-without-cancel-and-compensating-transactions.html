Reference: context.WithoutCancel & Compensating Transactions

The senior pattern for safely executing database cleanups and rollbacks after a request context has timed out or cancelled.

The Ghost Rollback Trap:

When an operation fails due to timeout (e.g. context deadline exceeded), passing the original ctx to your rollback closure causes all database queries inside the rollback (like ReleaseStock(ctx)) to immediately fail with context canceled!

1. What is context.WithoutCancel? (Go 1.21+)

context.WithoutCancel(parent) creates a child context that:

  • ✓ Ignores parent cancellation: It stays alive even if the parent times out or cancels.
  • ✓ Preserves values: It retains all request-scoped metadata (Trace IDs, Loggers, User IDs).

2. The Idiomatic Rollback Execution Pattern

func runRollback(ctx context.Context, cleanup func(context.Context) error) error {
    if cleanup == nil {
        return nil
    }

    // 1. Detach from parent cancellation while preserving context values:
    detachedCtx := context.WithoutCancel(ctx)

    // 2. Give the rollback its own dedicated, bounded timeout:
    rollbackCtx, cancel := context.WithTimeout(detachedCtx, 3*time.Second)
    defer cancel()

    // 3. Execute the compensating transaction safely:
    return cleanup(rollbackCtx)
}

3. Why Not Just Use context.Background()?

Approach Cancellation Signal Context Values (Tracing/Logs)
cleanup(ctx) ❌ Fails immediately if parent cancelled ✓ Preserved
cleanup(context.Background()) ✓ Does not cancel ❌ Loses all correlation IDs, loggers, trace info
cleanup(context.WithoutCancel(ctx)) 🏆 Independent lifecycle 🏆 All trace IDs & loggers preserved
