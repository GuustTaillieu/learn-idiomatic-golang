Reference: Graceful Shutdown, BaseContext & Streaming Teardown

How senior Go engineers shut down complex servers with long-lived streaming connections (SSE, WebSockets, gRPC) in under 10ms.

The Hidden Pitfall of http.Server.Shutdown():
"http.Server.Shutdown(ctx) does NOT cancel the request contexts of active connections. It waits for active handlers to return on their own."

If you have a streaming endpoint (like SSE GET /events) with an infinite loop, Shutdown() will hang until the shutdown timeout expires with context deadline exceeded.

1. The Solution: BaseContext

Configure http.Server.BaseContext to inherit from your application's signal.NotifyContext:

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

srv := &http.Server{
    Addr:    ":8080",
    Handler: httpHandler,
    // 💡 Propagates Ctrl+C cancellation to ALL active HTTP request contexts!
    BaseContext: func(l net.Listener) context.Context {
        return ctx
    },
}

2. What Happens on Ctrl+C

  1. User presses Ctrl+C → signal.NotifyContext cancels ctx.
  2. Because of BaseContext, r.Context().Done() fires immediately inside every active handler.
  3. Your SSE loop receives <-r.Context().Done() and exits cleanly in <1ms.
  4. srv.Shutdown(shutdownCtx) completes instantly with zero errors.

3. The Golden Order of Server Teardown

// 1. Stop accepting new web requests & cancel active streams:
shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
if err := srv.Shutdown(shutdownCtx); err != nil {
    slog.Warn("Forcing server close", "error", err)
    _ = srv.Close()
}

// 2. Stop the background queue and drain in-flight worker tasks:
queue.Stop()
