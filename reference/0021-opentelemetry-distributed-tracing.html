Reference: OpenTelemetry Distributed Tracing in Go

The industry-standard observability framework for tracing requests across HTTP handlers, background worker queues, and database transactions.

The Observability Golden Rule:
"Logs tell you what happened at a single instant in time. Metrics tell you the aggregate health of a component. Traces tell you the entire end-to-end journey of a request across goroutines, worker queues, and database queries."

1. Anatomy of a Trace & Spans

  • Trace: The tree of operations triggered by a single incoming request (e.g. checkout). Identified by a unique TraceID.
  • Span: A single named unit of work with a start time, duration, and status (e.g. sqlite.ReserveStock, payment.Charge). Identified by a SpanID.
  • Parent/Child Relationship: Spans are linked together through Go's context.Context.

2. Starting and Ending Spans

import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/trace"
)

var tracer = otel.Tracer("order-service")

func (p *OrderPlacing[T]) Process(ctx context.Context, order *domain.Order) (func(context.Context) error, error) {
    // 1. Start a child span from the incoming context
    ctx, span := tracer.Start(ctx, "processor.OrderPlacing",
        trace.WithAttributes(
            attribute.String("order.id", order.ID.String()),
            attribute.Int("order.amount", order.Amount),
        ),
    )
    defer span.End()

    // 2. Pass the enriched ctx to database operations
    tx, err := p.db.BeginTx(ctx, nil)
    if err != nil {
        span.RecordError(err)
        return nil, err
    }
    ...
}

3. Context Propagation Across Background Goroutines

When queuing work to an asynchronous worker pool or outbox dispatcher, the trace context must travel with the task!

type Task[T any] struct {
    ID       uuid.UUID
    Item     T
    TraceCtx context.Context // Preserves the originating request trace context!
}
