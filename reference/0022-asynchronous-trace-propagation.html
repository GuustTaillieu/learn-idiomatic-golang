Reference: Asynchronous Trace Propagation & W3C TraceContext

How senior Go engineers link asynchronous background worker goroutines back to the originating HTTP/RPC request trace.

The Asynchronous Context Paradox:
"Never pass an HTTP request context into a background goroutine or database outbox task. If the client closes the browser tab, the request context cancels, aborting the background worker! Instead, extract the W3C TraceContext string, serialize it with the task, and resume the trace using a fresh server context."

1. The W3C TraceParent Format

version-trace_id-parent_id-trace_flags
00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
  • version: Always 00 currently.
  • trace_id: 16-byte unique identifier shared across all services and goroutines for this operation.
  • parent_id: 8-byte ID of the span that enqueued the task.
  • trace_flags: 01 means recorded/sampled.

2. Injecting Trace Context into String Metadata

import "go.opentelemetry.io/otel/propagation"

func InjectTraceParent(ctx context.Context) string {
    carrier := propagation.MapCarrier{}
    propagation.TraceContext{}.Inject(ctx, carrier)
    return carrier["traceparent"]
}

3. Extracting and Resuming the Trace in a Worker

func ExtractTraceContext(ctx context.Context, traceParent string) context.Context {
    if traceParent == "" {
        return ctx
    }
    carrier := propagation.MapCarrier{"traceparent": traceParent}
    return propagation.TraceContext{}.Extract(ctx, carrier)
}

4. Connecting the Asynchronous Pipeline

  1. In RPC/HTTP Handler: 
    order.TraceParent = telemetry.InjectTraceParent(ctx)
orderStore.Save(ctx, order)
  2. In Background Worker: 
    // Use server base context so cancellation doesn't kill the worker,
// but extract the traceparent so spans link to the originating RPC request!
jobCtx := telemetry.ExtractTraceContext(workerCtx, order.TraceParent)
ctx, span := telemetry.StartSpan(jobCtx, "worker.ProcessOrder")
defer span.End()
