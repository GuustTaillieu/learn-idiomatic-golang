Reference: Transactional Outbox Claim Check & State Machine Lifecycle

The senior architecture pattern for preventing double-dispatch, racing worker writes, and orphaned state transitions.

The Core Problem:

If an asynchronous dispatcher queries SELECT * WHERE status = 'PENDING' every 500ms, any order that is submitted to the queue but not yet completed will be re-fetched and re-submitted on the next tick — causing an infinite dispatch loop and duplicate charges!

1. The Outbox Claim Check Pattern

The dispatcher must claim the job before or immediately upon submitting it to the queue:

func (d *OutboxDispatcher) DispatchOnce(ctx context.Context) error {
    pendingOrders, err := d.orderStore.GetPendingOrders(ctx)
    if err != nil {
        return err
    }

    for _, order := range pendingOrders {
        // 1. Claim the order in the database so next tick ignores it!
        order.Status = domain.OrderStatusRunning
        if err := d.orderStore.Save(ctx, order); err != nil {
            return err
        }

        // 2. Submit to worker queue
        if err := d.queue.Submit(ctx, order); err != nil {
            return err
        }
    }
    return nil
}

2. State Lifecycle Comparison

Phase Responsible Component Database State Event Broadcast
1. Ingestion HTTP POST /orders PENDING Created event
2. Claim & Dispatch OutboxDispatcher RUNNING Dispatched event
3. Execution (Parallel) Workers / Sagas In-Flight (No state change) None (work in progress)
4. Completion / Failure Transactional Commit / Rollback COMPLETED or FAILED Final Status event

3. Why Lifecycle State Must NOT Be a Parallel Processor Step

// ❌ Dangerous (Write Race):
p := processor.NewParallel(
    orderMarker,   // Goroutine 1 writes status = 'RUNNING' to DB
    orderPlacing,  // Goroutine 2 writes stock & order to DB at the exact same millisecond!
)

// ✅ Correct (Separation of Concerns):
// - Dispatcher claims the order: PENDING -> RUNNING
// - Pipeline executes business logic: Deduct stock + Charge card
// - Processor commits final result: RUNNING -> COMPLETED (or FAILED)
