Reference: Go Concurrency Primitives

Compressed mental models and syntax rules for idiomatic Go concurrency.

1. Channels (chan T)

Channels are typed conduits for sending and receiving values between goroutines. They coordinate work without manual locks.

  • Unbuffered (make(chan T)): Synchronous. A send blocks until another goroutine receives; a receive blocks until another sends. (Direct handoff).
  • Buffered (make(chan T, N)): Asynchronous up to capacity N. Sends only block when the buffer is full. Receives block when the buffer is empty.
  • Sending: ch <- value
  • Receiving: val := <-ch

2. Mutexes (sync.Mutex & sync.RWMutex)

Used when multiple goroutines must read or write shared in-memory state (like a map or struct field).

  • Race condition: Occurs when two goroutines access the same memory concurrently and at least one is a write.
  • sync.Mutex: Mutual exclusion. Only one goroutine can hold the lock at a time. 
    mu.Lock()
defer mu.Unlock() // guarantees unlock even if panic occurs
  • sync.RWMutex: Reader/Writer lock. Multiple readers can read simultaneously (mu.RLock() / defer mu.RUnlock()), but a writer gets exclusive access (mu.Lock() / defer mu.Unlock()).

3. Multiplexing with select

A select statement lets a goroutine wait on multiple channel operations simultaneously. It blocks until one case is ready.

select {
case task := <-q.tasks:
    // Process task
case <-ctx.Done():
    // Context timed out or was cancelled
    return ctx.Err()
}

4. Waiting Groups (sync.WaitGroup)

Coordinates waiting for a collection of goroutines to complete their execution.

  • wg.Add(1): Increment counter before launching the goroutine.
  • wg.Done(): Decrement counter when goroutine finishes (usually defer wg.Done()).
  • wg.Wait(): Blocks until the counter reaches zero.
