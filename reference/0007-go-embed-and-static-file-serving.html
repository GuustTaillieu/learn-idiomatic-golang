Reference: embed.FS, Static Assets & Single-Binary Applications

How senior Go engineers package full-stack applications, migrations, and assets into a single deployable machine binary.

The Go Superpower:

Go 1.16+ includes embed.FS in the standard library. You can compile HTML, CSS, JavaScript, and SQL migration files directly into the executable binary. No Docker volume mounts, no asset servers, zero runtime path errors.

1. The //go:embed Directive

package web

import (
    "embed"
    "io/fs"
    "net/http"
)

//go:embed static/*
var staticFiles embed.FS

// FileServer returns an http.Handler that serves embedded static files
func FileServer() http.Handler {
    // Strip the "static" prefix so index.html is served at "/"
    subFS, err := fs.Sub(staticFiles, "static")
    if err != nil {
        panic(err)
    }
    return http.FileServer(http.FS(subFS))
}

2. Wiring Static Files in Modern http.ServeMux (Go 1.22+)

mux := http.NewServeMux()

// API Routes
mux.HandleFunc("POST /api/orders", h.createOrder)
mux.HandleFunc("GET /api/events", h.streamEvents)

// Static Frontend (Catch-all root)
mux.Handle("GET /", web.FileServer())

3. Native Browser Real-Time Connection with EventSource

Server-Sent Events requires zero npm packages. Native JavaScript handles connection, streaming, and automatic reconnections:

// In your embedded browser JavaScript:
const events = new EventSource('/events');

events.onmessage = (event) => {
    const task = JSON.parse(event.data);
    console.log("Order event received:", task);
    updateOrderInDOM(task);
};

events.onerror = (err) => {
    console.warn("EventSource disconnected, browser will auto-reconnect...");
};
