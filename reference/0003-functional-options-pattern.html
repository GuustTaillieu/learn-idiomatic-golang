Reference: The Functional Options Pattern

The canonical Go pattern for constructors with optional parameters, defaults, and backwards compatibility.

1. Why This Pattern Exists in Go

Unlike languages like Python, C++, or C#, Go does not have:

  • Constructor overloading (e.g. NewServer(), NewServer(port), NewServer(port, timeout)).
  • Default parameter values (e.g. func NewServer(port int = 8080)).

If you add a new parameter to a constructor in Go, you break every single caller in your entire codebase! The Functional Options Pattern (invented by Rob Pike, refined by Dave Cheney) solves this permanently.

2. The Canonical Implementation

type Server struct {
    host    string
    port    int
    timeout time.Duration
}

// 1. Define the option function signature
type Option func(*Server)

// 2. Define option helper constructors
func WithPort(port int) Option {
    return func(s *Server) {
        s.port = port
    }
}

func WithTimeout(d time.Duration) Option {
    return func(s *Server) {
        s.timeout = d
    }
}

// 3. Constructor with sensible defaults
func NewServer(host string, opts ...Option) *Server {
    srv := &Server{
        host:    host,
        port:    8080,               // Default
        timeout: 30 * time.Second,   // Default
    }

    // Apply all options
    for _, opt := range opts {
        opt(srv)
    }

    return srv
}

3. How Callers Use It

// Uses all defaults:
s1 := NewServer("localhost")

// Overrides port only:
s2 := NewServer("localhost", WithPort(9000))

// Overrides both port and timeout:
s3 := NewServer("localhost", WithPort(9000), WithTimeout(5*time.Second))

4. Golden Rules for Functional Options

  1. Mutate Directly: Mutate the target struct pointer directly (func(s *Server)). You don't need a separate Opts struct.
  2. Sensible Defaults First: Always populate mandatory fields and sensible defaults before applying the option closures.
  3. Variadic ...Option: The variadic slice makes all options completely optional. Passing zero options is valid and clean.
