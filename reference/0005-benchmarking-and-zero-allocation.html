Reference: Benchmarking, Escape Analysis & Zero-Allocation Go

The senior Go engineer's cheat sheet for writing, measuring, and optimizing mechanical sympathy and memory throughput.

The Golden Rule of Go Performance:
"Do not guess. Benchmark, profile, and verify with -benchmem and compiler escape analysis."

1. Anatomy of a Benchmark Function

func BenchmarkProcessOrder(b *testing.B) {
    // 1. Expensive setup (runs once outside the loop)
    store := setupDatabase()
    order := domain.NewOrder(...)

    // 2. Reset the timer so setup time doesn't taint measurements!
    b.ResetTimer()
    b.ReportAllocs() // Equivalent to running with -benchmem

    // 3. The loop: b.N is dynamically tuned by the Go runtime
    for b.Loop() { // Go 1.24+ idiomatic loop (or for i := 0; i < b.N; i++)
        process(order)
    }
}

2. Essential Benchmark CLI Commands

Command Purpose
go test -bench=. ./... Runs all benchmarks across all packages.
go test -bench=. -benchmem ./... Reports heap bytes allocated (B/op) and allocation count (allocs/op).
go test -bench=BenchmarkName -count=5 Runs the benchmark 5 times to check for jitter and statistical stability.
go build -gcflags="-m" ./... Shows the Go compiler's escape analysis (which variables escape to heap).

4. The sync.Pool Pattern for Zero Allocations

Used in high-throughput hot paths (JSON serialization, buffer reuse, byte slices) to relieve the Garbage Collector:

var bufferPool = sync.Pool{
    New: func() any {
        // Allocated on heap once when pool is empty
        return new(bytes.Buffer)
    },
}

func FormatOrder(o *domain.Order) string {
    // 1. Borrow from pool
    buf := bufferPool.Get().(*bytes.Buffer)
    // 2. CRITICAL: Reset buffer state before using!
    buf.Reset()
    // 3. Always return to pool via defer
    defer bufferPool.Put(buf)

    buf.WriteString("Order: ")
    buf.WriteString(o.ID.String())
    return buf.String()
}
